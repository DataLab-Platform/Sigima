# Version 1.3 #

## Sigima Version 1.3.0 ##

### ✨ New features since version 1.2.0 ###

* **Brightness and contrast adjustment**: A new ROI-aware image processing performs numerically stable clipped linear remapping from persistent minimum and maximum bounds, preserves the source dtype and non-finite values, and exposes portable histogram context for native and browser interfaces. Tiny floating-point ranges and finite IEEE-754 extremes are supported without coupling headless computation to histogram rendering. The low-level helpers support floating-point arrays and integers up to 32 bits; they explicitly reject `int64` and `uint64` instead of risking precision loss at integer endpoints.
* **Portable graphical annotations**: Signals and images may now carry versioned, renderer-independent points, shapes, text, cursors and axis ranges. Annotations survive Sigima file round trips and supported image transformations, and are displayed consistently by the PlotPy and Matplotlib visualization backends. Existing PlotPy annotations remain readable and can be migrated explicitly while unknown application data is preserved. This implements [Issue #53](https://github.com/DataLab-Platform/Sigima/issues/53).
* **Interactive Plotly visualization**: Signals and images can now be inspected in a browser with zoom, pan and hover through the optional Plotly backend. Sigima also exposes dependency-free Plotly JSON builders for applications and notebooks, including portable annotation, ROI and geometry-result overlays.
* **Parameter validation**: Numeric creation and processing parameters now expose precise unconditional bounds, while mode-dependent and source-dependent constraints are checked before computation. Signed coordinate and grid conventions, as well as point-like or descending signal domains, remain supported.
* **Operation contracts for verifiable replay**: Every public computation function now declares a versioned contract (stable identifier, version, roles of its inputs, parameters and outputs, execution policy and global options read), so that an application can record what was computed and later recompute it with exactly the same meaning, even across DataLab Desktop and DataLab-Web. Signals, images, lists of inputs, conversions between signals and images and analysis results (tables and geometries) are all described. Replay of a contract is enabled only by an explicit, test-backed qualification declared next to the function, with its comparison rule (exact by default). 213 of the 215 operations are qualified: 161 must give identical results, and 52 (Fourier transforms and filters, recursive filters, curve fits, statistics and other reductions, transcendental functions, float32 data) accept a small justified tolerance between environments, measured by replaying the same calls between NumPy 1.26 / SciPy 1.10, NumPy 2.4 / SciPy 1.16 and Pyodide (WebAssembly, the runtime of DataLab-Web: NumPy 1.26 / SciPy 1.12); within an identical environment, their results must still be identical. The phase spectrum of signals and images is not qualified, because the phase of nearly real values differs between NumPy versions. Operations that are not qualified keep their identity: applications record it and explain why they do not replay them.
* **Explicit X alignment for signal difference**: When the two signals of a difference have different X grids, the second one is interpolated linearly on the grid of the first, under a named and versioned rule. The second grid must cover the first one (no extrapolation), both must be strictly increasing, and X and Y units must match exactly (no conversion): otherwise the operation is refused with a clear reason instead of producing a misleading result. The inputs are never modified.
* **Recorded X alignment for other signal operations**: The alignment historically applied by DataLab to signals with different X grids is now a named and versioned rule declared with each operation, so that a replay applies exactly the same alignment. For operations with a second signal (division, quadratic difference, arithmetic, convolution, deconvolution, complex signal construction, X-Y mode), the second signal is interpolated on the grid of the first one, keeping its first and last values outside its range. For operations combining several signals (sum, average, product, standard deviation, assembly into an image), all signals are interpolated on the smallest grid. Applications can thus warn before interpolating and record what was done.

### 🛠️ Bug Fixes since version 1.2.0 ###

* **Constant added to or subtracted from an integer image**: a constant outside the range of the image data type was converted to that type before the operation, a conversion whose result depends on the platform: adding -1 to a `uint8` image added 255 on x86-64 computers, and nothing in a web browser (WebAssembly). The constant is now truncated toward zero without being converted (adding -1 subtracts 1), as it already was for values within the range of the type.

### 🔧 Dependencies ###

* guidata 3.16.0 or later is now required (histogram-backed range items used by brightness and contrast adjustment).
